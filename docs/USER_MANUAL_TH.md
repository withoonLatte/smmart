## 1. ภาพรวมสถาปัตยกรรมระบบ

SUPER MARKET ERP ออกแบบด้วยสถาปัตยกรรม **Single Branch, Multi-Internal Locations** บนโครงสร้าง Cloudflare Edge Computing ระดับโลก:
- **Frontend:** React 18 + TypeScript + Vite + Tailwind CSS (สไตล์ Modern SaaS 2026, Glassmorphism, Micro-interactions)
- **Backend Edge API:** Cloudflare Workers (Hono Router) ตอบสนองความเร็วสูง < 50ms ทั่วประเทศ
- **Production Database:** Cloudflare D1 Distributed SQL Database (Serverless SQLite over Cloudflare Global Network)
- **Isolated Print Engine:** Hidden iframe Printing สำหรับเครื่องพิมพ์สลิปความร้อน (Thermal POS 58mm / 80mm) ตัดปัญหาหน้าพรีวิวขาวหรือหน้าเกิน 100%
- **Instant Client-side QR:** สร้าง PromptPay QR Code ฝั่งเบราว์เซอร์ผู้ใช้ทันทีใน 0.01 วินาที ไม่ต้องรอ Edge Network

## 2. คู่มือการใช้งานตามบทบาท

### 2.1 เจ้าของกิจการ / ผู้บริหารระดับสูง (Owner / Admin)
บัญชีสิทธิ์สูงสุด เข้าถึงและควบคุมได้ทุกฟังก์ชันของระบบ
- **Executive Dashboard:**
  - ตรวจสอบยอดขายรวมรายวัน รายสัปดาห์ รายเดือน
  - ติดตามกำไรขั้นต้น (Gross Profit), ยอดขายแยกตามหมวดหมู่สินค้า, ยอดภาษีขาย (VAT 7%)
  - สรุปสถานะสต๊อกวิกฤต (Low Stock Alert) และสินค้าใกล้หมดอายุ (Expiring Soon)
- **ระบบกำหนดสิทธิ์การใช้งาน (RBAC Permission Builder):**
  - เมนู `พนักงานและสิทธิ์` -> `กำหนดสิทธิ์บทบาท`
  - ติ๊กเปิด/ปิดฟังก์ชันการทำงานได้ละเอียดถึง 24 Permission Nodes แยกตามบทบาท
  - กำหนดว่าบทบาทใดสามารถดูต้นทุนสินค้า (Cost Price), อนุมัติการตัดสต๊อก หรือเข้าถึงรายงานการเงินได้
- **บันทึกกิจกรรมระบบ (Audit Logs):**
  - ตรวจสอบประวัติการล็อกอิน การขาย การยกเลิกบิล การปรับยอดสต๊อก และการเปลี่ยนรหัสผ่าน
  - บันทึกละเอียดพร้อมเวลา Timestamp, IP Address, ผู้กระทำ และข้อมูลก่อน/หลังเปลี่ยนแปลง
- **ตั้งค่าข้อมูลร้านค้า (Store Profile Settings):**
  - กำหนดชื่อร้าน เลขประจำตัวผู้เสียภาษี 13 หลัก หมายเลขสาขา (สำนักงานใหญ่ / สาขา 00000)
  - ที่อยู่และเบอร์โทรศัพท์สำหรับหัวบิลใบเสร็จรับเงิน/ใบกำกับภาษีอย่างย่อ
  - ข้อความท้ายใบเสร็จ (เช่น "ขอบคุณที่ใช้บริการ สินค้าซื้อแล้วไม่รับเปลี่ยนคืน")
  - หมายเลขพร้อมเพย์ (PromptPay ID) สำหรับรับชำระเงินหน้าร้าน

### 2.2 ผู้จัดการสาขา (Store Manager)
ผู้ควบคุมดูแลการปฏิบัติการประจำวัน ความถูกต้องของสต๊อก และการเงินหน้าร้าน
- **อนุมัติการตรวจนับสต๊อก (Stock Count Approval):**
  - เมนู `ตรวจนับสต๊อก` -> รายการงานนับสต๊อก
  - ระบบมีมาตรการความปลอดภัย **ป้องกัน Self-Approval (ห้ามผู้นับอนุมัติงานนับของตนเองเด็ดขาด)**
  - ผู้จัดการจะเห็นรายการผลต่าง (Discrepancy) ระหว่างยอดจริงในระบบกับยอดที่พนักงานนับได้
  - เมื่อกด `อนุมัติและปรับปรุงสต๊อก` ระบบจะรัน Atomic Transaction ปรับยอดสต๊อกและลงบันทึก Inventory Movement ชนิด `count_adjust` ทันที
- **อนุมัติใบสั่งซื้อสินค้า (PO Approval):**
  - ตรวจสอบใบสั่งซื้อที่ฝ่ายจัดซื้อสร้างขึ้น ตรวจสอบราคาเฉลี่ยและประวัติยอดจัดซื้อย้อนหลัง
  - กดอนุมัติเพื่อส่งให้ซัพพลายเออร์เปิดบิลส่งสินค้า
- **อนุมัติเปิด/ปิดกะแคชเชียร์ (Shift Oversight):**
  - ตรวจสอบเงินสดยกมาเริ่มต้นกะ (Opening Float) และเงินสดนำส่งเมื่อปิดกะ (Closing Cash)
  - ระบบคำนวณส่วนต่างเงินขาด/เงินเกิน (Over/Short) อัตโนมัติ ป้องกันการทุจริต
- **ควบคุมเพดานส่วนลดหน้าร้าน (Discount Policy Enforcement):**
  - แคชเชียร์สามารถให้ส่วนลดทั่วไปได้ตามโปรโมชั่น แต่หากเป็น **ส่วนลดพิเศษกำหนดเองที่เกิน ฿500 หรือเกิน 20% ของยอดซื้อ** ระบบจะปฏิเสธ (HTTP 403) เว้นแต่จะได้รับรหัสยืนยันจากผู้จัดการ

### 2.3 พนักงานแคชเชียร์ (Cashier POS)
ออกแบบหน้าจอจำหน่ายสินค้าสไตล์ Modern Dual-Pane ออกแบบพิเศษสำหรับพนักงานแคชเชียร์ทำงานรวดเร็วด้วยบาร์โค้ด
- **โครงสร้างหน้าจอ POS (Dual-Pane Layout):**
  - **ฝั่งซ้าย (Cart & Totals):**
    - รายการสินค้าในตะกร้า ตัวหนังสือขนาดใหญ่ อ่านชัดเจนแม้ยืนห่างหน้าจอ
    - แสดงชื่อสินค้า, บาร์โค้ด, จำนวน, ราคาต่อหน่วย, และราคารวม
    - ปรับจำนวน (+) (-) หรือลบรายการได้อย่างรวดเร็ว
    - สรุปยอดรวม (Subtotal), ส่วนลด (Discount), ภาษีมูลค่าเพิ่ม 7% (VAT Included), และยอดชำระสุทธิ (Grand Total ตัวหนาโดดเด่น)
  - **ฝั่งขวา (Payment Functions & Numpad):**
    - แป้นพิมพ์ตัวเลข (Touchscreen Numpad) สำหรับกรอกจำนวนเงินที่รับจากลูกค้า
    - ปุ่มลัดรับธนบัตรด่วน: `฿20`, `฿50`, `฿100`, `฿500`, `฿1,000`, และปุ่ม `พอดี (Exact)`
    - แสดงเงินทอน (Change Due) สีสันชัดเจน ป้องกันการทอนเงินผิดพลาด
- **ขั้นตอนการขายสินค้า:**
  1. ยิงบาร์โค้ดสินค้า หรือพิมพ์ค้นหาชื่อสินค้าในช่องค้นหา (ระบบรวมจำนวนสินค้าซ้ำให้อัตโนมัติ ป้องกันสต๊อกคลาดเคลื่อน)
  2. เลือกวิธีชำระเงิน: `เงินสด (Cash)`, `พร้อมเพย์ (PromptPay QR)`, `บัตรเครดิต (Card)`, หรือ `โอนเงิน (Transfer)`
  3. หากเลือกพร้อมเพย์ หน้าต่างจะแสดง QR Code รับเงินทันที (สร้างผ่านระบบ PromptPay Instant Engine ฝั่งผู้ใช้ ไม่ต้องรอเซิร์ฟเวอร์)
  4. เมื่อรับเงินครบถ้วน กดปุ่ม `คิดเงิน / ปิดการขาย (Done)`
- **ระบบ Idempotency Key ป้องกันการคิดเงินซ้ำ:**
  - แต่ละบิลจะผูกกับ Unique Idempotency Key ถาวรในเครื่อง หากเกิดสัญญาณเน็ตกระตุกหรือกดปุ่มซ้ำ ระบบจะไม่หักเงินหรือตัดสต๊อกซ้ำสองเด็ดขาด
- **ระบบค้างบิลและเรียกบิล (Hold & Resume Bill):**
  - กรณีลูกค้าขอแวะไปหยิบของเพิ่ม กดปุ่ม `พักบิล (Hold Order)` เพื่อเปิดรับลูกค้ารายถัดไปได้ทันที
  - เมื่อลูกค้าพร้อม กดปุ่ม `เรียกคืนบิล (Resume)` รายการสินค้าจะกลับมาครบถ้วน
- **ระบบสั่งพิมพ์ใบเสร็จ (Isolated Thermal Slip Engine):**
  - กดปุ่ม `พิมพ์ใบเสร็จ` ระบบจะประมวลผลข้อความและส่งไปยัง **Hidden iframe Document แยกต่างหาก**
  - ไม่เกิดการตัดขอบ ไม่เกิดหน้าว่าง 2 หน้า พิมพ์ออกเครื่องพิมพ์สลิปความร้อนคมชัด กึ่งกลางหน้ากระดาษ 100%

### 2.4 พนักงานตรวจนับสต๊อก (Stock Checker - Mobile Mode)
หน้าจอโหมดตรวจนับสต๊อกบนสมาร์ทโฟน/แท็บเล็ต ออกแบบสไตล์ Minimalist สะอาดตา
- **การตรวจนับแบบ Blind Count:**
  - พนักงานสแกนบาร์โค้ดสินค้าทีละชิ้น ระบบจะบวกจำนวนนับให้อัตโนมัติ
  - **ระบบไม่เปิดเผยจำนวนสต๊อกในระบบให้พนักงานเห็น** เพื่อป้องกันการเดาตัวเลขหรือกรอกข้อมูลเท็จ
- **แยกตรวจนับตามจุดเก็บ (Internal Locations):**
  - เลือกจุดเก็บที่รับผิดชอบ: ชั้นวางหน้าร้าน (`Retail Shelves`), โกดังใหญ่ (`Main Warehouse`), ห้องแช่เย็น (`Refrigerated Storage`), หรือหลังร้าน (`Back Store`)
- **การส่งมอบงานตรวจนับ (Submit Task):**
  - เมื่อนับครบตามพื้นที่ที่ได้รับมอบหมาย กดปุ่ม `ส่งผลตรวจนับให้ผู้จัดการ`
  - เมื่องานถูกส่งแล้ว ระบบจะล็อกสถานะเป็น `pending_approval` ทันที ป้องกันการแก้ไขตัวเลขย้อนหลัง

### 2.5 เจ้าหน้าที่คลังสินค้า (Warehouse Officer)
- **การรับสินค้าเข้าคลัง (Goods Receipt):**
  - อ้างอิงหมายเลขใบสั่งซื้อ (PO No.) ที่ได้รับอนุมัติ
  - ตรวจสอบจำนวนและสภาพสินค้าจริงก่อนกดยืนยันการรับเข้า (GR)
  - ระบุเลขล็อตการผลิต (Batch Number) และวันหมดอายุ (Expiry Date) เพื่อให้ระบบนำเข้าสต๊อกตามมาตรฐาน FIFO/FEFO
- **การย้ายสต๊อกภายในร้าน (Internal Location Transfer):**
  - เมนู `คลังสินค้า` -> `ย้ายตำแหน่งสินค้า`
  - ทำการเบิกย้ายสินค้า เช่น ย้ายจาก `โกดังใหญ่ (Main Warehouse)` ไปยัง `ชั้นวางจำหน่ายหน้าร้าน (Retail Shelves)`
  - สต๊อกแต่ละจุดจะอัปเดตตรงตามจริง พนักงาน POS จะเห็นสต๊อกหน้าร้านพร้อมขายทันที

---

### 2.6 เจ้าหน้าที่จัดซื้อ (Purchasing Officer)
- **จัดการข้อมูลซัพพลายเออร์ (Suppliers):**
  - บันทึกชื่อบริษัท เลขผู้เสียภาษี เงื่อนไขการชำระเงิน (Credit Terms เช่น 30 วัน, 60 วัน) และผู้ติดต่อ
- **สร้างใบสั่งซื้อ (Purchase Order - PO):**
  - ตรวจสอบสต๊อกสินค้าที่ถึงจุดสั่งซื้อซ้ำ (Reorder Point / Min Stock)
  - เลือกรหัสสินค้า ระบุจำนวนที่ต้องการสั่งซื้อ และราคาต้นทุนตามใบเสนอราคา
  - บันทึกสถานะร่าง (Draft) หรือส่งขออนุมัติจากผู้จัดการ (Submitted)

---

### 2.7 เจ้าหน้าที่ฝ่ายบัญชีและการเงิน (Accounting & Finance)
- **บันทึกค่าใช้จ่าย (Expense Management):**
  - บันทึกค่าใช้จ่ายดำเนินงาน เช่น ค่าน้ำ, ค่าไฟ, ค่าบรรจุภัณฑ์, เงินเดือนพนักงาน
  - แนบไฟล์หลักฐานใบเสร็จรับเงิน/ใบกำกับภาษี
- **รายงานภาษีมูลค่าเพิ่ม (VAT Report):**
  - คำนวณภาษีขายจากบิล POS อัตโนมัติ (VAT 7%)
  - รวบรวมภาษีซื้อจากเอกสารจัดซื้อสินค้า เพื่อเตรียมยื่นแบบ ภ.พ.30 ประจำเดือน
- **รายงานสรุปรายได้และกำไรขั้นต้น:**
  - สรุปยอดขายรวมเทียบกับต้นทุนสินค้า (COGS) และรายจ่ายประจำงวด

## 3. คู่มือการติดตั้งและการนำขึ้นระบบ

### สถาปัตยกรรมคลาวด์ (Cloudflare Deployment Stack)
- **โฮสติ้ง Frontend:** Cloudflare Pages
- **API Backend:** Cloudflare Workers Functions (`functions/api/[[route]].ts`)
- **ฐานข้อมูล:** Cloudflare D1 Database (`smmart-erp-db`)

### ขั้นตอนที่ 1: เตรียมสภาพแวดล้อมและติดตั้ง Dependencies
```bash
# ติดตั้งไลบรารีทั้งหมด
npm install

# รันระบบทดสอบ (Vitest Automated Tests)
npm test

# บิลด์แพ็กเกจ Production
npm run build
```

### ขั้นตอนที่ 2: ตั้งค่า Cloudflare D1 Database
```bash
# 1. สร้าง D1 Database บน Cloudflare (หากยังไม่มี)
npx wrangler d1 create smmart-erp-db

# 2. นำเข้าโครงสร้างตาราง (Production Schema)
npx wrangler d1 execute smmart-erp-db --remote --file=d1/schema.sql

# 3. นำเข้าข้อมูลเริ่มต้นและสิทธิ์ (Production Seed)
npx wrangler d1 execute smmart-erp-db --remote --file=d1/seed.sql
```

### ขั้นตอนที่ 3: Deploy Frontend & Functions ขึ้น Cloudflare Pages
```bash
# Deploy โฟลเดอร์ dist ไปยัง Cloudflare Pages
npx wrangler pages deploy dist --project-name=smmart
```

## 4. การสำรองและกู้คืนข้อมูล

### 4.1 การสำรองข้อมูล (Database Backup)
ควรสำรองข้อมูลเป็นประจำทุกวันหลังปิดยอดขายประจำวัน:
```bash
# ดึงข้อมูลทั้งหมดในฐานข้อมูล D1 ออกมาเป็นไฟล์ SQL Dump
npx wrangler d1 export smmart-erp-db --remote --output=backups/smmart-backup-$(date +%Y%m%d).sql
```
*ข้อแนะนำ:* เก็บไฟล์สำรองไว้บน Cloud Storage หรือพื้นที่จัดเก็บที่มีการเข้ารหัสปลอดภัย

### 4.2 การกู้คืนข้อมูลกรณีฉุกเฉิน (Disaster Recovery)
ในกรณีเกิดเหตุขัดข้องหรือต้องการย้อนสถานะข้อมูล:
```bash
# รันไฟล์สำรองข้อมูลกลับเข้าสู่ Cloudflare D1
npx wrangler d1 execute smmart-erp-db --remote --file=backups/smmart-backup-YYYYMMDD.sql
```
*การตรวจสอบความถูกต้องหลังกู้คืน:*
1. ล็อกอินด้วยบัญชี `owner`
2. ตรวจสอบยอดสต๊อกรวมในหน้า Inventory
3. ตรวจสอบประวัติบิลขายล่าสุดในหน้า Sales History

## 5. ความปลอดภัยและนโยบายรหัสผ่าน

### 5.1 นโยบายบังคับเปลี่ยนรหัสผ่าน (Mandatory Password Change)
- ทุกบัญชีเริ่มต้นจาก Seed Data จะถูกกำหนดค่า `force_password_change = 1`
- ในการเข้าสู่ระบบครั้งแรก เซิร์ฟเวอร์จะล็อกการเข้าถึง API ทุกเส้นทาง (HTTP 403 `FORCED_PASSWORD_CHANGE_REQUIRED`)
- ผู้ใช้งานจะได้รับอนุญาตให้เรียกเฉพาะ:
  - `GET /api/auth/me` (ตรวจสอบข้อมูลตนเอง)
  - `POST /api/auth/change-password` (เปลี่ยนรหัสผ่านใหม่)
  - `POST /api/auth/logout` (ออกจากระบบ)
- รหัสผ่านใหม่ต้องมีความยาวอย่างน้อย 8 ตัวอักษร มีตัวพิมพ์ใหญ่ ตัวพิมพ์เล็ก และตัวเลข

### 5.2 มาตรการป้องกัน Brute Force & Rate Limiting
- ระบบจะบันทึกประวัติการล็อกอินในตาราง `login_attempts`
- หากมีการล็อกอินผิดติดต่อกัน 5 ครั้งภายใน 15 นาที ระบบจะตัดการเชื่อมต่อและส่งรหัส **HTTP 429 Too Many Requests** ทันที เพื่อป้องกันการสุ่มรหัสผ่าน

### 5.3 หมายเหตุเรื่อง GitHub Token & Workflows
- **GitHub Personal Access Token (PAT):**
  - ในปัจจุบัน Token ที่ใช้เชื่อมต่อ Repository อาจไม่มีสิทธิ์ `workflow` scope
  - หากระบบพยายาม Push หรือแก้ไขไฟล์ในไดเรกทอรี `.github/workflows/` GitHub จะปฏิเสธการดำเนินการด้วยข้อความ `refusing to allow a Personal Access Token to create or update workflow`
  - หากต้องการเปิดใช้งาน GitHub Actions อัตโนมัติ ให้เข้าไปที่ **GitHub Settings -> Developer settings -> Personal access tokens** แล้วติ๊กเปิดสิทธิ์ `workflow` สำหรับ Token นั้น
